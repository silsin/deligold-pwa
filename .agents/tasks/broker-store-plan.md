# Implementation Plan — Broker Store Setup + Customer Store View

Grounded in code read during planning: `api/prisma/schema.prisma`, `api/src/stores/*`, `api/src/users/users.controller.ts` (multer pattern), `api/src/auth/public.decorator.ts`, `api/src/auth/guards/*`, `api/src/auth/current-user.decorator.ts`, `api/src/main.ts`, `api/src/common/{errors,money}.ts`, `src/router/index.js`, `src/stores/auth.js`, `src/views/{AccountView,BoardView}.vue`, `src/components/AppDrawer.vue`, `src/utils/{api,format,roles}.js`.

Two gaps found and resolved here (recorded so the implementer does not re-decide them):

- **Gap 1 — static file serving.** The API never serves uploaded files (the existing id-card upload stores `id-cards/<file>` but never displays it — `AccountView` only shows an "uploaded ✓" badge). The StoreView must render the logo as a real `<img src>` using "API base URL + logoPath", so the store-logos directory must be served. **Decision:** serve only the `store-logos` subdirectory at `/store-logos/` prefix via `app.useStaticAssets(...)` in `main.ts`, keeping id-cards private. Store `logoPath` as `store-logos/<file>` so `${apiBase}/${logoPath}` resolves. Also export `apiBase` from `src/utils/api.js` so the PWA can build that URL.
- **Gap 2 — `GET /stores/:id/products` scope.** The spec marks it `@Public()` "so unauthenticated customers can view" *and* says `listProducts(actor, storeId)` is "staff, same-broker" — these contradict, and a public per-store product list would let anyone enumerate store IDs. Customer viewing is already covered by the public `GET /stores/public/:brokerId`. **Decision:** `GET /stores/:id/products` is staff-only (same-broker), matching the `listProducts` signature; the public endpoint carries customer read access. This is the coherent, more secure choice.

`@Public()` works on the class-`@Roles(...STAFF)` StoresController because both guards resolve metadata with `getAllAndOverride([handler, class])`, so a method-level `@Public()` overrides the class guard. Verified in `jwt-auth.guard.ts` / `roles.guard.ts`.
